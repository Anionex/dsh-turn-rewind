# Turn Rewind 实施计划

## 目标

将 Turn Rewind 调整为面向普通用户的文件恢复功能，明确它与 Branch 的功能边界，并补齐多 Session、多层分叉和共享工作区场景下的安全处理。

## 实施内容

### 1. 简化用户界面和文案

- 将“工作区”“代码路径”“救援点”“恢复计划”等技术术语替换为用户容易理解的“项目文件”“自动备份”“恢复文件”等表述。
- 将默认操作改为“恢复文件并从这里继续”，第二个操作改为“只恢复文件”。
- 删除“仅回退对话”选项，由现有 Branch 功能统一承担只创建对话分支的场景。
- 删除重复确认复选框，将弹窗中的影响范围展示和最终主按钮点击作为确认流程。
- 根据所选模式动态显示“恢复并继续”或“恢复文件”按钮。
- 将底层检查点、分支、恢复计划和备份标识等信息收进默认折叠的操作详情。

### 2. 改善文件变化展示

- 使用“将恢复 N 个文件”替代“代码路径与该轮不同”。
- 按文件的实际变化显示“恢复之前的版本”“找回文件”“移除后来新增的文件”或“恢复文件权限”等结果。
- 文件较多时提供简洁预览和查看全部入口。
- 没有文件需要恢复时，不再把 Rewind 退化为 Branch，而是提示用户文件无需恢复，并引导使用 Branch 创建新对话。

### 3. 强化安全状态处理

- 正常恢复时显著告知用户当前文件会先自动备份，恢复失败时会自动还原。
- 文件在预览后发生变化时，使当前恢复操作失效，并要求重新检查。
- 检测同一工作区是否被其他活跃 Session 使用；存在并发修改风险时明确提示并阻止恢复。
- 明确告知共享工作区中的文件恢复会影响使用该目录的其他对话。
- 保留恢复前备份、计划过期检查、恢复后验证和失败补偿等底层安全机制。

### 4. 补齐多分叉场景

- 验证多层父子 Session 可以沿祖先链正确找到继承范围内的检查点。
- 验证多个兄弟分支之间的检查点互不混用。
- 验证子 Session 自己的检查点优先于祖先检查点。
- 验证每一层 Fork 的继承边界，禁止跨越 `seedLength` 使用祖先检查点。
- 覆盖重启后从持久化 Session 中恢复多层分叉关系的情况。
- 对父 Session 缺失、分叉关系循环、边界不一致和检查点被清理等异常情况安全失败。
- 覆盖多个分支同时预览、恢复或使用同一工作区时的冲突处理。

### 5. 调整接口、测试和文档

- 移除前端和后端中不再需要的“仅回退对话”模式及相关测试。
- 更新 UI、接口、错误状态和文件变化类型的自动化测试。
- 更新中英文 README、使用说明和产品截图，使其与新交互保持一致。
- 完成构建、完整测试、安装包检查和真实 Web 交互验证后再提交推送。

## 最终功能边界

- **Branch：**从所选回复创建新对话，项目文件保持不变。
- **Turn Rewind：**将项目文件恢复到所选回复完成时，并可选择是否从该位置继续新对话。
- **Change Ledger：**继续作为 Turn Rewind 底层的持久检查、自动备份和安全恢复引擎，不在普通用户主流程中暴露实现术语。
