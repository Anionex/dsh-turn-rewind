# Turn Rewind 对齐计划

## 目标

让 Web 端 Rewind 以用户消息为锚点：用户点击消息下方的回退图标，就能查看并恢复“发送这条消息之前”的项目文件，并可选择在新对话里重新开始。产品语义对齐 Claude Code，同时保留 Change Ledger 对完整工作树、自动备份、失败回滚和持久恢复的支持。

## 已实现内容

### 1. 用户消息锚点

- 回退图标从 Assistant 回复操作栏移到用户消息下方，排在时间和“复制”之后，无文字显示。
- 提示和弹窗标题统一为“回到发送这条消息之前”。
- 客户端按 `user/message` 的 `seq` 请求预览，不再用 Assistant Turn 尾部作为入口。
- 新对话创建后，会把所选用户消息的文字放回输入框。

### 2. 消息发送前保存文件

- 在每轮第一次 `agent/pre-step` 中、调用 `next()` 之前保存文件状态。
- 保存点精确绑定 `turn/start`，保证语义是 Agent 尚未处理这条用户消息。
- 同一工作树的保存操作串行执行。
- 保存失败会记录错误，但不会阻断用户 Turn；失败的消息不会伪造可用状态，也不会在 Turn 结束后重试并错误标记当前文件。

### 3. 恢复与重新开始

- **恢复文件并重新开始：**先恢复文件，再创建新对话，并把原消息文字放回输入框。
- **只恢复文件：**只改项目文件，当前对话保持不变。
- 第一条消息之前没有完整 Turn，使用 Host `session.create` 在同一目录创建空 Session。
- 后续消息使用 Host `session.fork`，边界是所选消息之前的上一条 `turn/end`。
- 原 Session 始终保留；只分支对话、文件不变的需求继续由原生“分支新对话”负责。

### 4. Git 状态处理

- HEAD 前进或当前分支变化不再直接阻止恢复；预览说明影响后，以 `allowHeadChange` 生成恢复计划。
- 恢复不会撤销 commit、切换分支、移动 HEAD 或修改 index；恢复结果可以表现为当前 HEAD 上的未提交修改。
- 合并、变基、cherry-pick 等 Git 操作状态变化继续阻止恢复。
- 预览后 HEAD、分支、Git 操作或所选文件再次变化，现有计划仍会失效。

### 5. 并发、分叉与失败处理

- 同一工作树只要存在正在运行的 Agent，包括来源 Session 自己，就阻止 Web 恢复；idle Session 不阻止。
- 子 Session 先使用自己的保存点，再沿祖先查找；兄弟分支互不混用。
- 祖先复用要求所选 `user/message` 和对应 `turn/start` 在每一层都低于 `seedLength`，并且边界完全一致。
- 父 Session 缺失、分叉循环或边界不一致时安全失败。
- 恢复前创建自动备份；创建新对话失败时，立即用备份补偿恢复前的文件状态。

### 6. 持久格式兼容

- 新 Turn 保存点写入 `turnStartSeq`。
- 旧版 `turnEndSeq` manifest 仍可读取，避免破坏格式版本 1，但不会被绑定到新的用户消息入口。
- `turn` manifest 必须且只能携带一种 Turn 边界。

## 最终功能边界

- **分支新对话（Branch）：**从现有对话创建分支，项目文件保持不变。
- **Turn Rewind：**恢复到发送所选用户消息之前的项目文件，并可选择创建新对话重新开始。
- **Change Ledger：**提供持久保存、差异预览、短期恢复计划、自动备份、原子恢复、失败回滚和重启对账，不在普通用户主流程中暴露底层术语。
